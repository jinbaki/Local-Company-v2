# UI/UX 명세

Last updated: 2026-05-29

## 1. UX 원칙

- 대표는 PM과 대화하는 화면에서 대부분의 일을 처리한다.
- 화면은 절차보다 현재 상태를 보여준다.
- 버튼은 최소화한다.
- 한 화면에는 한 가지 주 목적만 둔다.
- 기술 로그보다 사업 정보, 산출물, 결정사항을 우선한다.
- PM이 무엇을 판단했고, 대표가 무엇을 결정해야 하는지 분명히 보여준다.

## 2. 주요 화면

### 2.1 홈

목적:

- 대표가 오늘 봐야 할 것을 한눈에 보여준다.

구성:

- 대표 결정 필요
- 진행 중 캠페인
- 최근 PM 보고
- 자동 실행 중 작업
- 막힌 작업

홈에서 하지 않는 것:

- 상세 실행 로그 표시
- 산출물 본문 표시
- 복잡한 설정 변경

### 2.2 사업부 홈

목적:

- 사업부의 장기 맥락과 캠페인을 관리한다.

구성:

- 사업부 이름과 설명
- 사업부 리드
- 캠페인 목록
- 사업부 직원
- 사업부 공통 문서 바로가기
- 새 캠페인 생성

캠페인 목록은 표 형태가 기본이다.

컬럼:

- 생성일
- 캠페인명
- PM
- 상태
- 마지막 갱신

### 2.3 캠페인 운영판

V2의 중심 화면이다.

레이아웃:

```text
좌측: PM 대화
우측: 캠페인 운영판
```

좌측 PM 대화:

- 대표 메시지 입력
- PM 답변
- PM이 답변 중인지 표시
- 현재 PM이 참고 중인 주요 문서 표시

우측 운영판:

- 현재 목표
- PM 현재 판단
- 진행 중 작업
- 대표 결정 필요
- 산출물
- 직원 상태

운영판은 탭을 많이 만들지 않는다. 필요하면 섹션 접기/펼치기를 사용한다.

### 2.4 산출물 저장소

목적:

- 산출물을 읽고 버전을 확인한다.

구성:

- 산출물 목록
- 상태 필터
- 산출물 새 탭 열기
- 버전 이력
- PM 리뷰
- 관련 태스크
- 관련 결정사항

산출물 본문은 가능하면 새 탭 뷰어에서 본다. 캠페인 운영판 안에 긴 산출물을 직접 넣지 않는다.

### 2.5 결정함

목적:

- 대표가 결정해야 하는 항목만 모은다.

구성:

- 결정 제목
- 왜 결정이 필요한지
- PM 추천안
- 선택지
- 각 선택지의 영향
- 영향을 받는 작업/산출물
- 결정하기 버튼

결정함은 홈과 캠페인 운영판 양쪽에서 접근 가능해야 한다.

### 2.6 조직

목적:

- 사업부 직원과 캠페인 배정을 확인한다.

구성:

- 사업부 직원 목록
- 캠페인 배정 현황
- 직원별 세션 상태
- 직원별 최근 산출물
- 직원 프로필

게임식 초상화나 과한 캐릭터 UX는 사용하지 않는다. 이름, 포지션, 담당 업무가 중심이다.

## 3. 버튼 원칙

대표가 자주 보는 버튼:

- PM에게 보내기
- 자동 실행 시작
- 자동 실행 중지
- 결정하기
- 산출물 보기
- 수정 요청하기
- 새 캠페인 만들기

피해야 할 버튼:

- 내부 단계명을 그대로 노출한 버튼
- "정리 생성", "구조 갱신"처럼 사용자가 의미를 추측해야 하는 버튼
- 같은 기능을 여러 위치에서 다르게 부르는 버튼

## 4. 상태 표시

상태는 기술 결과보다 사용자가 이해할 수 있는 문장으로 표시한다.

나쁜 예:

```text
pm_quality_review_parse_failed
```

좋은 예:

```text
PM 리뷰 결과를 구조화하지 못했습니다. 산출물은 저장되어 있으므로 PM에게 다시 검토를 요청할 수 있습니다.
```

## 5. 자동 실행 표시

자동 실행 중에는 반드시 현재 작업을 보여준다.

표시 항목:

- 현재 실행 중인 직원
- 현재 산출물
- 현재 단계: 작업지시, 산출물 작성, PM 리뷰, 재작업, 대표 결정 대기
- 완료된 산출물 수
- 남은 산출물 수
- 마지막 오류

## 6. 산출물 수정 UX

대표는 산출물을 읽고 PM에게 자연어로 말한다.

예:

```text
2번 가격 기준을 4번 정산표에도 맞춰주세요.
1번 후보 리스트는 석촌역과 가락시장역 기준 5km로 다시 찾아주세요.
```

PM은 다음을 정리한다.

- 수정 대상 산출물
- 무엇을 고칠지
- 왜 고칠지
- 관련 산출물이 있는지
- 대표 결정이 필요한지

화면에는 중복 설명을 많이 보여주지 않는다.

## 7. 시각 디자인 방향

- Slack, Notion, Linear, Asana에 가까운 업무형 UI.
- 차분한 색상.
- 넓은 여백보다 정보 밀도와 가독성 우선.
- 박스 남발 금지.
- 표, 리스트, 접기/펼치기, 상태 뱃지를 적절히 사용.
- 산출물 본문은 문서처럼 읽히게 한다.

## 8. 모바일/외부 사용

초기 V2는 데스크톱 우선이다.

외부 사용은 다음 단계에서 고려한다.

- 읽기 전용 산출물 공유
- 대표 결정함 모바일 확인
- PM 메시지 알림
- Slack/Firebase 연동
