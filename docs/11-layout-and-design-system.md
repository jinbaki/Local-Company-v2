# 레이아웃과 UI 기준

Last updated: 2026-05-29

이 문서는 Local Company V2의 화면이 흔들리지 않도록 레이아웃, 컴포넌트, 시각 위계 기준을 고정한다.

## 1. 디자인 목표

V2는 업무용 도구다. 느낌은 Slack, Notion, Linear, Asana에 가깝다.

목표:

- 대표가 지금 할 일을 빠르게 이해한다.
- PM이 업무를 운영하고 있다는 느낌을 준다.
- 산출물과 결정사항이 문서처럼 읽힌다.
- 버튼과 박스가 많아 사용자가 피로해지지 않는다.

피해야 할 느낌:

- 게임식 조직 관리
- 과한 카드 UI
- 색이 많은 대시보드
- 큰 통계 박스 중심 화면
- 내부 개발 도구 같은 버튼명

## 2. 화면 밀도

기준:

- 정보 밀도는 중간 이상.
- 여백은 넉넉하지만 비어 보이면 안 된다.
- 대시보드 카드보다 표, 리스트, 문서형 섹션을 우선한다.

권장:

```text
데스크톱 기본 폭: 1280px 이상
메인 콘텐츠 최대 폭: 페이지 성격에 따라 1120~1440px
문서 본문 폭: 760~880px
PM 대화 폭: 380~440px
Rail 폭: 56~64px
Top Bar 높이: 52~56px
```

## 3. 전역 레이아웃 토큰

### 간격

8px 기준 시스템을 사용한다.

| 토큰 | 값 | 용도 |
| --- | --- | --- |
| `space-1` | 4px | 아이콘과 텍스트 사이 |
| `space-2` | 8px | 작은 요소 간격 |
| `space-3` | 12px | 리스트 행 내부 |
| `space-4` | 16px | 섹션 내부 |
| `space-5` | 24px | 섹션 간격 |
| `space-6` | 32px | 큰 영역 간격 |

### 라운드

| 토큰 | 값 | 용도 |
| --- | --- | --- |
| `radius-sm` | 4px | 입력, 작은 버튼 |
| `radius-md` | 6px | 표 필터, 작은 패널 |
| `radius-lg` | 8px | 모달, 큰 패널 |

카드는 8px를 넘지 않는다.

### 선

| 토큰 | 값 |
| --- | --- |
| 기본 border | `1px solid #DADDE3` |
| 약한 border | `1px solid #ECEEF2` |
| 강한 border | `1px solid #C7CBD3` |

## 4. 색상 기준

단색 테마로 치우치지 않는다. 보라색, 진한 남색, 베이지 계열이 전체를 지배하지 않게 한다.

권장 팔레트:

| 역할 | 색 |
| --- | --- |
| 배경 | `#F7F8FA` |
| 표면 | `#FFFFFF` |
| 기본 텍스트 | `#1F2328` |
| 보조 텍스트 | `#667085` |
| 약한 텍스트 | `#98A2B3` |
| 경계선 | `#DADDE3` |
| 주요 액션 | `#2563EB` |
| 성공 | `#16803C` |
| 경고 | `#B7791F` |
| 위험 | `#C2410C` |
| 대기 | `#6B7280` |

상태 색은 텍스트와 작은 뱃지에만 쓴다. 큰 영역 배경을 상태 색으로 칠하지 않는다.

## 5. 타이포그래피

기본:

```text
font-family: system UI, Apple SD Gothic Neo, Segoe UI, sans-serif
letter-spacing: 0
```

크기:

| 스타일 | 크기 | 굵기 | 용도 |
| --- | --- | --- | --- |
| Page Title | 22px | 700 | 페이지 제목 |
| Section Title | 16px | 700 | 섹션 제목 |
| Body | 14px | 400 | 본문 |
| Body Strong | 14px | 600 | 표 주요 값 |
| Small | 12px | 400 | 보조 정보 |
| Caption | 11px | 500 | 상태 뱃지 |

금지:

- viewport width 기반 폰트 크기.
- 음수 letter spacing.
- 작은 패널 안에 과한 대형 제목.

## 6. 버튼 기준

버튼은 의미가 명확해야 한다.

### 버튼 유형

| 유형 | 용도 |
| --- | --- |
| Primary | 주요 실행. 예: 자동 실행 시작, 결정 저장 |
| Secondary | 보조 실행. 예: 산출물 보기 |
| Ghost | 가벼운 이동 또는 보조 액션 |
| Danger | 삭제, 초기화, 중지 |
| Icon | 보내기, 열기, 편집 등 익숙한 기능 |

### 버튼명 원칙

좋은 버튼명:

- 자동 실행 시작
- 결정 저장
- 산출물 보기
- PM에게 수정 요청
- 직원 추가

나쁜 버튼명:

- 구조 갱신
- 정리 생성
- 실행 설계 저장
- 파싱 재시도
- Scribe update

내부 작업명은 UI에 노출하지 않는다.

## 7. 표 기준

V2의 핵심 정보는 표로 보여주는 것이 좋다.

표를 쓰는 곳:

- 캠페인 목록
- 산출물 목록
- 직원 목록
- 작업 큐
- 대표 결정 목록

표 규칙:

- 행 높이 44~52px.
- 주요 컬럼은 왼쪽 정렬.
- 상태는 작은 뱃지로 표시.
- 긴 텍스트는 두 줄까지만 허용하고 상세는 클릭해서 본다.
- 표 안에 큰 버튼을 여러 개 넣지 않는다.

## 8. 패널과 카드 기준

패널은 영역을 나눌 때만 쓴다.

허용:

- PM 대화 패널
- 운영판의 큰 섹션 구분
- 모달
- 산출물 요약

금지:

- 카드 안의 카드.
- 모든 정보를 둥근 박스에 넣기.
- 같은 화면에 비슷한 카드 6개 이상 반복.
- 페이지 섹션 전체를 떠 있는 카드처럼 처리.

## 9. 섹션 기준

섹션은 문서처럼 보여야 한다.

권장 구조:

```text
섹션 제목             보조 액션
짧은 설명 또는 상태
표/리스트/문서 본문
```

섹션 간격은 24px를 기본으로 한다.

## 10. PM 대화 UI 기준

PM 대화는 앱의 핵심이다.

구성:

- 대화 헤더: PM 이름, 역할, 상태
- 메시지 목록
- 시스템 이벤트
- 입력창

입력창:

- 1줄에서 시작.
- 최대 6줄까지 자동 확장.
- Enter는 보내기.
- Shift+Enter는 줄바꿈.
- 보내기 버튼은 입력창 오른쪽에 아이콘으로 둔다.

스크롤:

- 사용자가 최신 메시지 근처에 있을 때만 자동 스크롤한다.
- 과거 메시지를 읽는 중이면 자동으로 아래로 내리지 않는다.
- 새 메시지가 오면 "새 메시지" 표시를 띄운다.

## 11. 운영판 UI 기준

운영판은 캠페인의 현재 상태를 보여준다.

섹션 순서:

1. 현재 목표
2. PM 현재 판단
3. 대표 결정 필요
4. 진행 중 작업
5. 산출물
6. 직원 상태
7. 최근 보고

각 섹션은 최대한 짧게 보여준다. 상세는 별도 화면이나 새 탭으로 이동한다.

## 12. 산출물 UI 기준

산출물 목록:

- 표.
- 번호, 제목, 담당자, 상태, 최신 버전, 갱신일.
- 행 클릭으로 상세 요약.
- 새 탭 보기 버튼 제공.

산출물 본문:

- 새 탭 뷰어.
- Markdown은 문서처럼 렌더링.
- 표는 가로 스크롤 허용.
- 본문 최대 폭은 760~880px.
- PM 리뷰는 본문 아래 또는 오른쪽 보조 영역.

## 13. 상태 뱃지 기준

상태는 짧고 일관되게 쓴다.

| 상태 | 표시 |
| --- | --- |
| draft | 초안 |
| ready | 준비 |
| queued | 대기 |
| running | 실행 중 |
| in_review | 검토 중 |
| needs_revision | 수정 필요 |
| approved | 완료 |
| blocked | 막힘 |
| failed | 실패 |

기술 에러 코드는 기본 화면에 그대로 보여주지 않는다.

## 14. 알림과 피드백

모든 버튼 실행은 결과를 알려야 한다.

알림 문구 예:

- 캠페인을 만들었습니다.
- PM이 답변을 준비하고 있습니다.
- 산출물 2개를 새 버전으로 수정했습니다.
- 대표 결정이 필요해 자동 실행을 멈췄습니다.
- 직원 세션이 준비되지 않아 작업을 시작하지 못했습니다.

실패 알림은 다음 행동을 포함해야 한다.

나쁜 예:

```text
실패했습니다.
```

좋은 예:

```text
직원 세션이 준비되지 않아 작업을 시작하지 못했습니다. 조직 화면에서 세션을 시작한 뒤 다시 실행하세요.
```

## 15. 반응형 기준

데스크톱:

- Rail + Top Bar + 메인 2컬럼.
- PM 대화와 운영판 동시 표시.

태블릿:

- PM 대화와 운영판을 탭으로 전환.
- 산출물 본문은 새 화면.

모바일:

- 홈, 결정함, PM 보고, 산출물 읽기 우선.
- 복잡한 업무 그래프 편집은 제공하지 않는다.

## 16. 접근성 기준

- 모든 버튼은 키보드 포커스가 보여야 한다.
- 상태 색만으로 의미를 전달하지 않는다.
- 아이콘 버튼에는 툴팁과 접근성 라벨이 있어야 한다.
- 표 행 클릭 외에 명시적 액션도 제공한다.
- 텍스트 대비는 WCAG AA 수준을 목표로 한다.

## 17. 구현 전 UI 체크리스트

새 화면을 만들기 전에 다음을 확인한다.

- 이 화면의 주 목적은 하나인가?
- 대표가 이 화면에서 해야 할 행동이 명확한가?
- PM 대화와 상태 정보가 충돌하지 않는가?
- 같은 정보가 중복 표시되지 않는가?
- 내부 기술 용어가 노출되지 않는가?
- 긴 산출물 본문이 운영판을 밀어내지 않는가?
- 버튼을 눌렀을 때 성공/실패를 알 수 있는가?
- 작은 화면에서 텍스트가 겹치지 않는가?
