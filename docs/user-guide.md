# 사용 매뉴얼

Last updated: 2026-05-30

## 1. 앱 열기

서버를 실행한 뒤 브라우저에서 `http://127.0.0.1:8788`을 연다.

왼쪽 메뉴에는 홈, 사업부, 캠페인, 산출물, 결정함, 조직, 설정 화면이 있다.

## 2. 사업부 만들기 또는 선택하기

상단 사업부 선택 상자에서 현재 사업부를 고른다.

새 사업부가 필요하면 상단의 `+` 버튼이나 사업 화면의 `사업부 만들기`를 누른다.

입력할 것:

- 사업부 이름
- 사업부 폴더 이름
- 사업부 설명
- 사업부 리드 / PM 이름

사업부 폴더 이름은 `data/divisions/` 아래에 만들어질 폴더명이다. 공백 없이 한글, 영문, 숫자, 하이픈, 밑줄을 사용할 수 있다. 사업부를 만들면 그 사업부 전용 PM 직원이 함께 만들어진다.

사업부 홈의 `사업부 수정`을 누르면 사업부 이름, 설명, 리드 / PM 이름을 바꿀 수 있다. 폴더 이름은 이미 저장된 파일 경로라 이 화면에서는 바꾸지 않는다.

기본 사업부는 삭제하지 않는다. 새로 만든 사업부는 사업부 홈의 `사업부 삭제`로 지울 수 있고, 그 사업부에 연결된 캠페인, 직원, 로컬 폴더도 함께 삭제된다.

## 3. 첫 캠페인 만들기

사업부 화면에서 캠페인을 만든다.

좋은 캠페인 제목 예:

```text
콘텐츠 제작 캠페인
```

요약에는 이번 캠페인에서 얻고 싶은 결과를 짧게 적는다.

## 4. PM과 대화하기

캠페인 화면에서 PM에게 요청을 남긴다.

예:

```text
제품 소개 콘텐츠를 목표, 작업, 산출물로 나눠주세요.
```

PM 답변 뒤에는 목표, 작업, 산출물 요청이 운영판에 정리된다.

PM이 참고해야 할 자료가 있으면 PM 대화 패널의 `참고자료 추가`를 누른다. 메모, URL, 파일 업로드를 등록할 수 있고, 등록된 참고자료는 다음 PM 답변과 PM 액션 정리에 함께 전달된다. 업로드한 파일은 해당 캠페인의 `knowledge/source-materials` 폴더에 저장된다.

PM이 캠페인을 혼자 처리하기 어렵다고 판단하면 `PM 팀 제안`에 필요한 직원 구성을 올린다. 제안은 PM이 만든 JSON 액션으로 저장되며, 앱은 이름, 역할, 임무, 인원 수 같은 형식만 검증한다. `팀 생성 승인`을 누르면 제안된 직원들이 캠페인에 배정되고 작업 큐가 열린다.

## 5. 자동 실행하기

대기 작업이 있으면 `자동 실행 시작`을 누른다. PM 팀 제안이 승인 대기 중이면 직원 실행 큐는 열리지 않는다.

기본 설치는 `mock` 실행으로 동작한다. 실제 Codex CLI를 연결하려면 `.env`에서 `CODEX_RUNNER=codex-cli`로 바꾼다. 실행 뒤 산출물은 PM 리뷰 대기 상태가 되고, 다시 자동 실행하면 PM 리뷰가 진행된다.

## 6. 산출물 확인하기

산출물 화면에서 목록을 고르고 상세를 연다.

확인할 것:

- 산출물 번호와 제목
- 현재 버전
- 본문
- PM 리뷰
- 수정 요청 이력
- 관련 산출물 관계

수정이 필요하면 상세 화면에서 `PM에게 수정 요청`을 남긴다.

## 7. 결정함 처리하기

PM이 대표 판단이 필요하다고 본 항목은 결정함에 열린다.

결정함에서 추천안과 선택지를 확인하고 답변을 저장한다. 답변을 저장하면 그 결정 때문에 막힌 작업이 다시 이어질 수 있다.

## 8. 인계 보고서 만들기

캠페인 화면에서 `인계 보고서`를 누른다.

생성되는 파일:

- `reports/human-todos.md`
- `reports/campaign-status.md`
- `reports/owner-brief.md`

보고서에는 사람이 해야 할 일, 다음 AI 작업, 산출물과 결정 상태가 나뉘어 정리된다.

## 9. 캠페인 완료 처리

캠페인은 완료 전까지 계속 진행 중인 업무로 다룬다.

일단 마무리할 캠페인이라면 `캠페인 완료`를 누른다. 완료 뒤에도 산출물과 보고서는 폴더에 남는다.

테스트용으로 만든 캠페인을 완전히 지우려면 캠페인 화면의 `캠페인 삭제`를 누른다. PM 대화, 업무, 산출물, 결정함 항목, 로컬 캠페인 폴더가 함께 삭제되므로 보관할 내용이 있으면 먼저 인계 보고서를 만든다.

## 10. 실제 Codex 사용하기

설정 화면의 `Codex 연결`에서 실행 방식을 `Codex CLI`로 바꾸고 저장한다. PM, worker, scribe는 `gpt-5.5`를 기본값으로 쓴다. 계정에서 `gpt-5.3-codex` 같은 Codex 전용 모델을 지원하면 설정 화면에서 직접 바꿀 수 있다.

Codex 계정 로그인이 필요하면 `설치/로그인 터미널 열기`를 누른다. 앱이 새 로컬 터미널을 열고 Codex 로그인 전용 흐름을 실행한다. 이미 로그인되어 있다고 나오면 창을 닫고 설정 화면으로 돌아온다. 로그인 주소나 기기 코드가 나오면 브라우저 안내를 따라 로그인한다. `Continue anyway? [y/N]`가 보이면 `y`를 입력하고 Enter를 누른다. 완료 후 설정 화면으로 돌아와 `연결 확인`을 누른다. 공식 npm CLI가 없거나 Windows 앱 별칭이 막혀 있으면 열린 터미널에서 설치/업데이트와 `codex login --device-auth` 실행까지 진행한다. 로그인은 열린 터미널에서 진행하며 앱은 비밀번호나 API 키를 저장하지 않는다.

`연결 확인`을 누르면 앱이 Codex CLI 설치, 로그인 상태, 네트워크 연결을 확인하고 `연결됨`, `로그인 필요`, `설치 필요` 같은 상태로 표시한다.

## 11. 데모로 둘러보기

설치 뒤 바로 체험하려면 다음 순서로 실행한다.

```bash
npm run seed:demo
```

PowerShell:

```powershell
$env:DATA_DIR = ".\data-sample"
npm run dev
```

데모 캠페인에는 PM 대화, 산출물, 결정함, 인계 보고서가 미리 들어 있다.
