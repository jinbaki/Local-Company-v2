# 와이어프레임 명세

Last updated: 2026-05-29

이 문서는 Local Company V2 구현 전에 화면 구조를 고정하기 위한 와이어프레임 명세다. 구현자는 기능을 만들기 전에 이 문서의 화면 목적, 배치, 구성 요소, 금지 요소를 기준으로 삼는다.

## 1. 전체 방향

V2의 화면은 "PM이 운영하는 업무 워크스페이스"여야 한다.

따라서 화면은 다음 질문에 답해야 한다.

1. 대표가 지금 봐야 할 것은 무엇인가?
2. PM이 지금 무엇을 판단하고 있는가?
3. 어떤 작업이 진행 중인가?
4. 어떤 산출물이 나왔는가?
5. 대표가 결정해야 하는 것은 무엇인가?

V2는 사용자가 Part 번호를 찾아다니는 앱이 아니다. 대표가 PM과 대화하고, PM이 업무를 운전하며, 화면은 그 결과를 읽기 좋게 보여주는 앱이다.

## 2. 전역 앱 셸

### 목적

사업부, 캠페인, 산출물, 결정함, 조직을 빠르게 오갈 수 있는 기본 골격이다.

### 데스크톱 와이어프레임

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ Top Bar                                                                      │
│ Local Company · 사업부 선택 · 캠페인 검색                         사용자/설정 │
├──────┬───────────────────────────────────────────────────────────────────────┤
│ Rail │ Page Header                                                           │
│      │ 제목 · 현재 맥락 · 주요 액션                                           │
│ 홈   ├───────────────────────────────────────────────────────────────────────┤
│ 사업 │                                                                       │
│ 캠페 │ Main Content                                                           │
│ 산출 │                                                                       │
│ 결정 │                                                                       │
│ 조직 │                                                                       │
│ 설정 │                                                                       │
└──────┴───────────────────────────────────────────────────────────────────────┘
```

### 레이아웃 규칙

- 좌측 Rail은 좁게 유지한다. 권장 폭은 56~64px.
- Rail에는 아이콘과 짧은 라벨만 둔다.
- Top Bar 높이는 52~56px.
- Page Header는 현재 페이지의 목적과 주요 액션만 담는다.
- Main Content는 페이지마다 하나의 주 목적만 가진다.
- 긴 설명 문구를 화면 위쪽에 많이 넣지 않는다.

### 금지

- 좌측 사이드바에 긴 목록을 계속 쌓지 않는다.
- 캠페인 목록과 조직 목록을 Rail 안에 넣지 않는다.
- Page Header 아래에 또 다른 큰 헤더를 반복하지 않는다.

## 3. 홈

### 목적

대표가 오늘 확인해야 할 내용을 보여준다.

### 화면 구성

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ 홈                                                                           │
│ 오늘 확인할 결정과 진행 중인 캠페인                                           │
├──────────────────────────────────────────────────────────────────────────────┤
│ 대표 결정 필요                                                               │
│ ┌──────────────────────────────────────────────────────────────────────────┐ │
│ │ 결정 제목                         캠페인            PM 추천       상태   │ │
│ │ 가격 기준 확정                    콘텐츠 유통       2안 추천      대기   │ │
│ │ 콘텐츠 주제 후보 확정            제품 소개 콘텐츠   직접 제공     대기   │ │
│ └──────────────────────────────────────────────────────────────────────────┘ │
│                                                                              │
│ 진행 중 캠페인                                                               │
│ ┌──────────────────────────────────────────────────────────────────────────┐ │
│ │ 캠페인명              PM        현재 초점              진행 상태  갱신   │ │
│ │ 콘텐츠 제작 캠페인     캠페인 PM    메시지 구조화          실행 중    5분 전 │ │
│ │ 콘텐츠 유통 검증       김하늘       산출물 수정            검토 중    1시간 전│ │
│ └──────────────────────────────────────────────────────────────────────────┘ │
│                                                                              │
│ 최근 PM 보고                                                                 │
│ - 콘텐츠 제작 캠페인: 초안 검토 산출물에서 대표 직접 확인 범위 확인 필요      │
│ - 콘텐츠 유통 검증: 정산표와 손익 시뮬레이션 기준 가격 정합성 보정 완료         │
└──────────────────────────────────────────────────────────────────────────────┘
```

### 핵심 요소

- 대표 결정 필요
- 진행 중 캠페인
- 최근 PM 보고
- 자동 실행 중 작업
- 막힌 작업

### 기본 인터랙션

- 결정 행 클릭: 결정 상세로 이동.
- 캠페인 행 클릭: 캠페인 운영판으로 이동.
- 최근 PM 보고 클릭: 해당 캠페인 보고 위치로 이동.

### 금지

- 홈에 긴 산출물 본문을 넣지 않는다.
- 홈에서 작업 큐 로그를 직접 보여주지 않는다.
- 큰 통계 카드 4~6개를 상단에 반복 배치하지 않는다.

## 4. 사업부 홈

### 목적

사업부의 장기 맥락과 캠페인 목록을 보여준다.

### 화면 구성

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ 콘텐츠 유통 사업부                                             새 캠페인     │
│ 신선식품/건강식품의 B2B 납품 모델을 검증하고 운영한다.                       │
├──────────────────────────────────────────────────────────────────────────────┤
│ 사업부 요약                                                                  │
│ 리드: 김하늘 · 직원 5명 · 진행 캠페인 2개 · 최근 갱신 10분 전                  │
│                                                                              │
│ 캠페인                                                                       │
│ ┌──────────────────────────────────────────────────────────────────────────┐ │
│ │ 생성일       캠페인명              PM       상태        현재 초점          │ │
│ │ 05.29        콘텐츠 유통 검증       김하늘      실행 중     산출물 수정        │ │
│ │ 05.29        제품 소개 콘텐츠       김하늘      목표 설계   고객군 정리        │ │
│ └──────────────────────────────────────────────────────────────────────────┘ │
│                                                                              │
│ 사업부 직원                                                                  │
│ PM 리드 · 사업부 운영     콘텐츠 담당 · 고객 발굴     파트너십 담당           │
│                                                                              │
│ 문서                                                                         │
│ 사업부 개요 · 대표 의견 · 운영 기준 · 공통 지식                               │
└──────────────────────────────────────────────────────────────────────────────┘
```

### 핵심 요소

- 사업부명
- 사업부 설명
- 리드
- 캠페인 표
- 사업부 직원 요약
- 사업부 공통 문서 바로가기

### 금지

- 사업부 홈에 캠페인 운영판을 섞지 않는다.
- 사업부 홈에서 목표 설계, 실행 설계 같은 세부 섹션을 보여주지 않는다.
- 캠페인 선택 박스를 상단에 따로 두지 않는다. 캠페인은 표에서 선택한다.

## 5. 새 캠페인 생성 모달

### 목적

캠페인의 최소 정보를 받고 PM을 배정한다.

### 화면 구성

```text
┌──────────────────────────────────────────────┐
│ 새 캠페인 만들기                              │
├──────────────────────────────────────────────┤
│ 캠페인명                                      │
│ [ 콘텐츠 제작 캠페인                         ] │
│                                              │
│ 짧은 설명                                     │
│ [ 콘텐츠 주제와 핵심 메시지를 분석해 ...     ] │
│                                              │
│ PM                                           │
│ (•) 사업부 리드가 겸임                         │
│ ( ) 기존 직원 선택                            │
│ ( ) 새 PM 생성                                │
│                                              │
│ [취소]                              [만들기] │
└──────────────────────────────────────────────┘
```

### 기본값

- PM은 사업부 리드가 겸임한다.
- 캠페인명은 필수다.
- 설명은 선택이지만 PM 초기 브리프에 들어간다.

## 6. 캠페인 운영판

### 목적

대표가 PM과 대화하며 캠페인 전체를 운영하는 핵심 화면이다.

### 화면 구성

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ ← 사업부    콘텐츠 제작 캠페인                           자동 실행 시작      │
│ PM 캠페인 PM · 현재 상태: 실행 중 · 현재 초점: 사례 구조화와 근거 검토           │
├───────────────────────────────┬──────────────────────────────────────────────┤
│ PM 대화                        │ 운영판                                       │
│                               │                                              │
│ 캠페인 PM PM                      │ 현재 목표                                    │
│ 대표님, 지금은 주제 분석과 ...    │ 여러 정보 및 콘텐츠 주제를 분석하고...          │
│                               │                                              │
│ 대표(나)                       │ PM 현재 판단                                 │
│ 보도자료 근거도 같이 봐주세요. │ - 추가 서치는 보도자료 근거 확인에 한정        │
│                               │ - 대표 직접 수행 범위 확인 필요               │
│ 캠페인 PM PM                      │                                              │
│ 네, 그건 근거 검토 태스크에... │ 대표 결정 필요                               │
│                               │ 1. 콘텐츠 주제 후보를 대표가 제공할지       │
│                               │ 2. 내부 수행 범위 메모 제공 가능 여부          │
│                               │                                              │
│                               │ 진행 중 작업                                  │
│                               │ 콘텐츠 주제 분석 보고서      주제 담당   작성 중    │
│                               │ 사례 구조화 보고서          이서윤   대기       │
│                               │                                              │
│ [메시지 입력             ▶]   │ 산출물                                       │
│                               │ 001 콘텐츠 주제 분석 보고서      작성 중          │
│                               │ 002 콘텐츠 소재 선별 보고서      검토 필요        │
└───────────────────────────────┴──────────────────────────────────────────────┘
```

### 레이아웃 규칙

- PM 대화는 좌측 고정 영역이다. 권장 폭은 380~440px.
- 우측 운영판은 캠페인 상태를 문서와 표 중심으로 보여준다.
- 우측은 너무 많은 박스를 만들지 않는다. 섹션 제목과 표, 리스트를 기본으로 한다.
- PM 대화 입력창은 입력량에 따라 1~6줄까지 커진다.

### 운영판 섹션 순서

1. 현재 목표
2. PM 현재 판단
3. 대표 결정 필요
4. 진행 중 작업
5. 산출물
6. 직원 상태
7. 최근 보고

### 금지

- Part 1~6 탭을 핵심 네비게이션으로 노출하지 않는다.
- 우측 운영판에 긴 산출물 본문을 직접 넣지 않는다.
- "구조 갱신", "정리 생성"처럼 내부 작업명을 버튼으로 노출하지 않는다.

## 7. PM 대화 패널

### 목적

대표와 PM의 대화를 유지하는 고정 작업 공간이다.

### 화면 구성

```text
┌───────────────────────────────┐
│ PM 대화                        │
│ 캠페인 PM PM · 캠페인 PM          │
├───────────────────────────────┤
│ 09:10 대표(나)                 │
│ 목표를 다시 정리해주세요.       │
│                               │
│ 09:11 캠페인 PM PM                │
│ 좋습니다. 지금 목표는...       │
│                               │
│ 09:12 시스템                   │
│ 목표 1개와 태스크 3개가 갱신됨 │
├───────────────────────────────┤
│ [메시지 입력                 ] │
│ Enter 보내기 · Shift+Enter 줄바꿈 │
└───────────────────────────────┘
```

### 상태 표시

- PM 답변 중
- PM이 참고 문서를 읽는 중
- 액션 반영 완료
- 대표 확인 필요
- 오류 발생

### 금지

- 대화가 길다고 자동으로 무조건 맨 아래로 끌어내리지 않는다.
- 사용자가 위쪽 메시지를 읽고 있으면 자동 스크롤을 멈춘다.
- 입력창 아래에 의미 없는 설명 텍스트를 두지 않는다.

## 8. 업무 그래프 화면

### 목적

목표, 태스크, 산출물, 직원, 결정사항의 관계를 한눈에 보여준다.

### 기본 화면

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ 업무 그래프                                             보기: 목표 중심       │
├──────────────────────────────────────────────────────────────────────────────┤
│ 목표                                                                         │
│ 여러 정보 및 콘텐츠 주제를 분석하고 전략적으로 이력서를 작성한다                │
│                                                                              │
│ ├─ 콘텐츠 주제 분석                                                             │
│ │  ├─ 태스크: 핵심 메시지 분해                            주제 담당                 │
│ │  └─ 산출물: 콘텐츠 주제 분석 보고서                     작성 중               │
│ │                                                                            │
│ ├─ 콘텐츠 소재 선별                                                             │
│ │  ├─ 태스크: source data에서 소재 추출       소재 담당                 │
│ │  └─ 산출물: 콘텐츠 소재 선별 보고서                     검토 필요             │
│ │                                                                            │
│ └─ 근거 검토                                                                  │
│    ├─ 태스크: 보도자료와 내부 수행 범위 분리           윤태호                 │
│    └─ 산출물: 근거 검토 보고서                         대기                  │
└──────────────────────────────────────────────────────────────────────────────┘
```

### 보기 모드

- 목표 중심
- 산출물 중심
- 직원 중심
- 막힌 작업 중심

### 금지

- 처음부터 복잡한 노드 그래프 캔버스를 만들지 않는다.
- 공개 버전 초기 구현에서는 트리/리스트 기반 구조가 더 명확하다.
- 노드 드래그 편집은 후순위다.

## 9. 산출물 저장소

### 목적

산출물을 목록으로 보고, 각 산출물을 새 탭 뷰어에서 읽는다.

### 화면 구성

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ 산출물                                                       상태 필터: 전체 │
├──────────────────────────────────────────────────────────────────────────────┤
│ 번호  산출물명                    담당자   상태        최신 버전   갱신      │
│ 001   콘텐츠 주제 분석 보고서        주제 담당   작성 중      v001       5분 전    │
│ 002   콘텐츠 소재 선별 보고서        소재 담당   검토 필요    v002       12분 전   │
│ 003   사례 구조화 보고서           이서윤   대기         -          -         │
│ 004   콘텐츠 초안                  초안 담당   대기         -          -         │
│                                                                              │
│ 선택 산출물 요약                                                              │
│ 002 콘텐츠 소재 선별 보고서                                                     │
│ PM 리뷰: 대표 직접 수행 범위와 회사 성과가 일부 섞여 있음                     │
│ 관련 태스크: source data 추출, source data 분류                                    │
│ [새 탭에서 열기] [PM에게 수정 요청]                                           │
└──────────────────────────────────────────────────────────────────────────────┘
```

### 규칙

- 목록은 표로 보여준다.
- 본문은 새 탭 뷰어에서 본다.
- 화면 안에 긴 Markdown 본문을 넣지 않는다.
- 산출물 번호는 안정적으로 유지한다.

## 10. 산출물 뷰어

### 목적

산출물을 문서처럼 읽고, 버전과 PM 리뷰를 확인한다.

### 화면 구성

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│ 002 콘텐츠 소재 선별 보고서                         v002 ▾     PM에게 수정 요청 │
```

## 12. 조직 화면

### 목적

사업부 직원과 캠페인 배정, 세션 상태를 관리한다.

### 화면 구성

```text

├──────────────────────────────────────────────────────────────────────────────┤
```

### 규칙

- 직원 초상화는 사용하지 않는다.
- 이름, 포지션, 담당 캠페인, 세션 상태를 중심으로 한다.
- 중복 직원이 나타나면 안 된다.

## 13. 설정 화면

### 목적

앱과 모델, 데이터 경로를 관리한다.

### 구성

- 데이터 폴더
- Codex PM 모델
- Codex 직원 모델
- Codex 서기 모델
- 자동 실행 최대 반복 횟수
- 백업 위치
- 로그 보관 기간

### 금지

- 일반 사용자가 자주 만져야 하는 옵션을 설정에 숨기지 않는다.
- PM 대화와 캠페인 운영에 필요한 기능을 설정 화면으로 보내지 않는다.

## 14. 모바일 기준

초기 V2는 데스크톱 우선이다.

모바일에서는 다음만 우선 지원한다.

- 홈
- 대표 결정함
- PM 최근 보고 읽기
- 산출물 읽기

모바일에서 복잡한 업무 그래프 편집이나 자동 실행 제어는 후순위다.

## 15. 구현 수용 기준

V2 첫 UI 구현은 다음 기준을 통과해야 한다.

- 대표가 홈에서 오늘 결정할 일을 볼 수 있다.
- 사업부 홈에서 캠페인 표를 보고 캠페인에 들어갈 수 있다.
- 캠페인 운영판에서 PM 대화와 현재 업무 상태를 동시에 볼 수 있다.
- 산출물 본문은 새 탭 뷰어에서 읽는다.
- 결정함은 홈과 캠페인 운영판에서 모두 접근 가능하다.
- 조직 화면은 직원 중복 없이 표로 보인다.
- Part 1~6 탭이 핵심 네비게이션으로 노출되지 않는다.
- "정리 생성", "구조 갱신" 같은 내부 버튼명이 보이지 않는다.
