# 제품 브리프

Last updated: 2026-05-29

## 1. 제품 한 줄 정의

Local Company V2는 대표가 AI PM과 대화하면, AI PM이 목표, 직원, 업무, 산출물, 결정사항을 관리하며 로컬 컴퓨터에서 일을 진행하는 AI 회사 워크스페이스다.

## 2. 제품 목표

대표가 복잡한 실행 절차를 직접 조작하지 않고도 AI 협의체를 운영할 수 있게 한다.

대표는 PM과 대화한다. PM은 업무를 구조화하고, 필요한 AI 직원을 구성하고, 작업을 지시하고, 산출물을 검토하고, 대표에게 필요한 결정만 요청한다.

## 3. 핵심 사용자

| 사용자 | 목적 |
| --- | --- |
| 대표 | PM과 대화하며 프로젝트, 캠페인, 업무 방향을 결정한다. |
| 캠페인 PM | 목표와 실행을 관리하고 직원에게 일을 배분한다. |
| AI 직원 | 작업지시를 받아 산출물을 작성한다. |
| 사람 직원 | AI가 할 수 없는 외부 확인, 실제 연락, 현장 조사, 승인 업무를 수행한다. |

## 4. 핵심 가치

- 대표가 AI 직원 여러 명을 직접 관리하지 않아도 된다.
- PM이 업무를 주도하고 대표에게 필요한 판단만 요청한다.
- 산출물은 자유로운 형식으로 만들고 버전 관리한다.
- 로컬 컴퓨터와 Codex 세션을 활용해 개인 업무 환경을 유지한다.
- 모든 업무 맥락, 대화, 산출물, 결정사항이 폴더와 데이터로 남는다.

## 5. V2의 핵심 전환

기존 구조:

```text
Part 1 목표 설정
Part 2 실행 설계
Part 3 인력 구성
Part 4 실행
Part 5 검토
Part 6 인계
```

V2 구조:

```text
PM 대화
  -> PM 액션
    -> 업무 그래프 갱신
    -> 작업 큐 실행
    -> 산출물 저장
    -> PM 리뷰
    -> 대표 결정/보고
```

V2에서는 Part가 사용자의 주요 화면이 아니다. Part에 해당하는 상태는 내부 운영 상태로만 사용한다.

## 6. 대표 시나리오

### 6.1 새 캠페인 시작

1. 대표가 사업부에서 새 캠페인을 만든다.
2. PM이 생성된다.
3. 대표가 PM에게 아이디어나 목표를 말한다.
4. PM이 목표 후보, 리스크, 필요한 조사, 다음 행동을 제안한다.
5. 대표가 방향을 승인하면 업무 그래프가 생성된다.

### 6.2 실행 계획 수립

1. 대표가 "실행 가능한 업무로 쪼개주세요"라고 말한다.
2. PM이 목표별 태스크와 산출물을 제안한다.
3. 시스템이 태스크, 산출물, 역할을 공식 상태로 저장한다.
4. PM이 필요한 직원을 추천한다.

### 6.3 자동 실행

1. PM이 작업 큐를 만든다.
2. AI 직원들이 작업지시를 받아 산출물을 만든다.
3. PM이 산출물을 검토한다.
4. 통과하면 완료 처리한다.
5. 부족하면 PM이 재작업을 지시한다.
6. 대표 결정이 필요하면 자동 실행을 멈추고 결정함에 올린다.

### 6.4 산출물 수정

1. 대표가 산출물을 읽는다.
2. 대표가 PM에게 수정 의견을 말한다.
3. PM이 어떤 산출물을 어떻게 수정할지 정리한다.
4. 작업 큐가 수정 작업을 실행한다.
5. 새 산출물 버전이 생성된다.

## 7. 성공 기준

- 대표는 Part 번호를 몰라도 캠페인을 진행할 수 있다.
- PM과 대화하면 목표, 태스크, 산출물, 직원, 결정사항이 자동 정리된다.
- PM은 단순 템플릿 답변자가 아니라 사업 운영자처럼 제안하고 검토한다.
- 산출물은 독립 객체로 관리되고 최신 버전을 쉽게 확인할 수 있다.
- 자동 실행은 대표 결정이 필요한 순간 안전하게 멈춘다.
- 대표는 홈과 결정함만 봐도 오늘 할 일을 알 수 있다.

## 8. 비목표

- 처음부터 외부 협업 SaaS처럼 만드는 것.
- 모든 업무를 완전 자동화하는 것.
- 사람이 해야 하는 현장 확인까지 AI가 했다고 단정하는 것.
- PM과 직원의 모든 내부 로그를 대표에게 노출하는 것.
