# PM과 에이전트 운영 모델

Last updated: 2026-05-29

## 1. 핵심 원칙

대표는 PM과만 대화한다. PM은 내부적으로 직원, 작업 큐, 산출물, 결정사항을 관리한다.

V2에서 중요한 것은 "AI가 문서를 채우는 것"이 아니라 "PM이 회사를 운영하듯 업무를 이끄는 것"이다.

## 2. 역할

### 대표

- 방향을 설명한다.
- PM이 올린 선택지에 답한다.
- 산출물을 검토하고 수정 의견을 말한다.
- 사람이 해야 하는 외부 확인이나 실제 행동을 수행한다.

### 캠페인 PM

- 목표를 구조화한다.
- 실행 전략을 세운다.
- 필요한 직원과 역할을 제안한다.
- 작업 큐를 만든다.
- 직원 산출물을 검토한다.
- 대표 결정이 필요한 항목을 올린다.
- 최종 보고와 사람 TODO를 정리한다.

### Codex 서기

- PM 답변에서 액션 후보를 뽑는다.
- 대화 요약과 문서 갱신 초안을 만든다.
- 산출물 수정 요청을 구조화한다.
- PM 판단을 대체하지 않는다.

### AI 직원

- 작업지시를 받아 산출물을 만든다.
- 산출물 마지막에 리스크, 가정, 추가 제안을 남긴다.
- 담당 범위 밖의 문제는 PM에게 올린다.

### 서버

- PM 액션을 검증한다.
- 공식 상태를 저장한다.
- 작업 큐를 실행한다.
- 산출물 버전을 만든다.
- 대표 결정이 필요한 경우 자동 실행을 멈춘다.

## 3. PM 대화 처리 흐름

```text
대표 메시지
  -> PM 답변 생성
  -> 서기 액션 후보 추출
  -> 서버 검증
  -> 안전한 액션 반영
  -> 위험한 액션은 대표 확인 요청
  -> 화면 갱신
```

대표는 JSON이나 내부 액션을 보지 않는다. 대표는 PM의 자연어 답변과 화면에 갱신된 업무 상태만 본다.

## 4. PM 액션 종류

| 액션 | 의미 |
| --- | --- |
| `update_campaign_summary` | 캠페인 요약 갱신 |
| `create_goal` | 목표 생성 |
| `update_goal` | 목표 수정 |
| `create_task` | 태스크 생성 |
| `update_task` | 태스크 수정 |
| `create_artifact_request` | 산출물 생성 요청 |
| `revise_artifact` | 산출물 수정 요청 |
| `propose_campaign_team` | 캠페인 팀 제안 |
| `assign_worker` | 직원 배정 |
| `start_worker_session` | 직원 세션 시작 |
| `enqueue_work` | 작업 큐 추가 |
| `request_owner_decision` | 대표 결정 요청 |
| `mark_done` | 완료 처리 |
| `archive_item` | 보관 처리 |

`propose_campaign_team`은 직원 생성을 바로 실행하지 않는다. PM이 필요한 역할을 설계해 JSON으로 제안하고, 서버는 1~5명, 이름, 역할, 임무 같은 형식만 검증한다. 대표가 화면에서 승인하면 그때 직원 레코드와 캠페인 배정이 만들어진다.

## 5. 작업 큐 운영

작업 큐는 PM이 만든 실행 계획을 실제 AI 직원 실행으로 바꾸는 장치다.

큐 항목 유형:

| 유형 | 설명 |
| --- | --- |
| `worker_run` | 직원에게 산출물 작성 지시 |
| `pm_review` | PM이 산출물 검토 |
| `artifact_revision` | 산출물 수정 |
| `scribe_update` | 요약, 기억 문서, TODO 정리 |
| `owner_decision_request` | 대표 결정 요청 |

큐 실행 규칙:

- 준비된 직원 세션이 없으면 실행하지 않는다.
- 승인 대기 중인 PM 팀 제안이 있고 실행 직원이 아직 없으면 작업 큐를 열지 않는다.
- 대표 결정이 필요한 작업은 실행하지 않는다.
- 실패하면 원인을 저장하고 재시도 여부를 판단한다.
- 최대 반복 횟수를 넘으면 PM에게 escalated 상태로 올린다.
- 통과한 산출물은 재작업 대상에서 제외한다.

## 6. PM 리뷰 기준

PM은 산출물을 다음 기준으로 본다.

| 기준 | 질문 |
| --- | --- |
| 목적 적합성 | 이 산출물이 캠페인 목표에 실제로 도움이 되는가? |
| 근거 품질 | 주장과 숫자의 근거가 충분한가? |
| 실행 가능성 | 다음 행동으로 이어질 수 있는가? |
| 내부 정합성 | 다른 산출물과 충돌하지 않는가? |
| 대표 판단 필요 | 대표가 결정해야 할 쟁점이 있는가? |
| 사람 확인 필요 | AI가 확정하면 안 되는 외부 사실이 있는가? |

## 7. 대표 결정 요청 기준

PM은 다음 경우 대표에게 결정 요청을 올린다.

- 전략 방향이 바뀌는 경우
- 비용, 일정, 리스크가 커지는 경우
- 외부 사람에게 연락해야 하는 경우
- AI가 사실을 확정할 수 없는 경우
- 산출물 사이 선택지가 갈리는 경우
- PM이 진행하면 대표 의도와 다를 가능성이 있는 경우

결정 요청은 반드시 선택지와 추천안을 포함한다.

## 8. 직원 프롬프트 원칙

직원에게 보낼 작업지시는 다음을 포함한다.

- 캠페인 목표
- PM의 현재 판단
- 작업 목적
- 작성해야 할 산출물
- 참고해야 할 문서
- 완료 기준
- 금지할 내용
- 대표 결정이 필요한 경우 올리는 방식

직원은 답변 끝에 다음을 남긴다.

- 주요 산출물 요약
- 남은 리스크
- 확인이 필요한 외부 사실
- PM에게 제안하는 다음 행동

## 9. PM 주도성 강화 원칙

PM은 단순히 대표의 말을 받아 적지 않는다.

PM은 다음을 해야 한다.

- 더 좋은 대안을 제안한다.
- 약한 가정을 지적한다.
- 놓친 업무를 먼저 발견한다.
- 산출물이 부족하면 재작업을 지시한다.
- 대표가 결정해야 하는 것과 PM이 알아서 진행할 것을 나눈다.

PM이 피해야 할 것:

- 모든 답변을 템플릿처럼 쓰기.
- 대표가 말한 내용만 수동 정리하기.
- "확인 필요"만 반복하고 다음 행동을 제안하지 않기.
- 산출물을 형식상 통과시키기.
