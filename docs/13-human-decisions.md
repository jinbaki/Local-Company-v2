# 사람 판단 필요 항목

Last updated: 2026-05-29

이 문서는 구현 중 사람이 판단해야 하거나, 지금은 기본값으로 진행했지만 나중에 대표 확인이 필요한 항목을 모은다.

## 열린 항목

| ID | 항목 | 현재 기본값 | 사람이 판단할 내용 | 필요한 시점 | 상태 |
| --- | --- | --- | --- | --- | --- |
| HD-001 | SQLite 런타임 기준 | Node.js 24의 내장 `node:sqlite` 사용 | 배포 대상까지 Node.js 20을 지원하려면 `better-sqlite3` 같은 외부 드라이버로 바꿀지 결정해야 한다. | 더 넓은 배포 대상을 잡기 전 | open |
| HD-002 | 실제 Codex 모델명 | PM `gpt-5.5`, worker `gpt-5.3-codex`, scribe `gpt-5.3-codex` | `codex-cli` runner는 구현되어 있지만, 공개/운영 전에 계정별 사용 가능 모델과 비용 기준을 확정해야 한다. | 실제 운영 전 | open |
| HD-003 | 기본 조직 seed | 기본 사업부, PM `김하늘`, 실행 직원 `박도현`, 대표 표시명 `대표(나)` | 공개 버전 기본값은 한국식 이름으로 정했다. 실제 운영에서 고정 이름을 바꾸고 싶으면 사업부 수정에서 바꾼다. | 실제 운영에 쓰기 전 | resolved |
| HD-004 | PM 액션 자동 반영 정책 | 목표/태스크/산출물/결정 요청은 자동 반영, 실행/세션/완료/보관은 제한 | 실제 운영에서 어떤 액션까지 자동 반영할지 대표가 확정해야 한다. | 실제 Codex 서기 연결 전 | open |
| HD-005 | HTML 산출물 보안 정책 | HTML 산출물은 sandbox iframe으로 표시 | 외부 HTML, 스크립트, 네트워크 리소스, 파일 접근을 어디까지 허용할지 확정해야 한다. | HTML 산출물을 실제 업무에 쓰기 전 | open |
| HD-006 | 실제 직원 실행 정책 | `codex-cli` worker runner가 산출물 버전을 생성할 수 있음 | 자동 실행 승인 범위, 비용/시간 제한, 중단 정책을 운영 기준으로 확정해야 한다. | 실제 운영 전 | open |
| HD-007 | PM 리뷰와 재작업 기준 | `codex-cli` PM 리뷰가 승인/재작업/대표 결정을 JSON으로 반환 | 산출물 승인 기준, 재작업 요청 기준, 대표에게 멈춰야 하는 조건, 최대 재작업 횟수를 운영 기준으로 확정해야 한다. | 실제 운영 전 | open |
| HD-008 | 대표 결정 후 자동 재개 범위 | 대표가 결정을 저장하면 해당 결정 때문에 막힌 큐를 자동으로 `queued`로 되돌림 | 모든 결정 답변을 자동 재개로 볼지, 일부는 PM 재검토 또는 수동 실행 확인을 거치게 할지 확정해야 한다. | 실제 자동 실행 운영 전 | open |
| HD-009 | 수정 요청 중복 판단 기준 | 같은 산출물과 완전히 같은 수정 지시 문자열만 중복으로 처리 | 의미가 비슷하지만 문구가 다른 수정 요청을 같은 요청으로 묶을지, 별도 요청으로 처리할지 기준을 정해야 한다. | 실제 PM 수정 플로우 운영 전 | open |
| HD-010 | 사람 TODO 추출 기준 | 열린 결정, 막힌 큐, 사람/대표/승인/확인/외부/연락/비용 등 키워드가 있는 미승인 작업과 산출물을 사람 TODO로 분류 | 어떤 문구를 사람 처리 항목으로 볼지, 외부 연락과 단순 내부 확인을 나눌지 기준을 확정해야 한다. | 실제 인계 보고서 운영 전 | open |
| HD-011 | 공개 라이선스 | `LICENSE`는 All rights reserved | GitHub 공개 시 오픈소스 라이선스로 둘지, 내부 공유 전용으로 둘지, 상업적 사용 허용 범위를 정해야 한다. | 외부 공개 전 | open |
| HD-012 | PM 팀 제안 승인 범위 | PM이 JSON으로 팀을 제안하고 대표가 승인하면 직원 생성/배정 | 실제 운영에서 팀 제안 승인 뒤 작업 큐까지 자동으로 열지, 승인 후 PM 재검토 단계를 둘지 확정해야 한다. | 실제 자동 실행 운영 전 | open |

## 구현자가 임시로 정한 기본값

| ID | 항목 | 임시 결정 | 이유 | 되돌릴 수 있는 시점 |
| --- | --- | --- | --- | --- |
| ID-001 | UI 프레임워크 | React | 앱 셸과 상태 기반 화면 구현에 적합하다. | Phase 0 이후 |
| ID-002 | 첫 서버 방식 | Express + Vite middleware | 한 주소에서 API와 앱을 함께 확인하기 쉽다. | Phase 0 이후 |
| ID-003 | Phase 1 PM 실행 | mock PM 답변 | 실제 Codex runner 전에도 캠페인, 대화 저장, 운영판 흐름을 검증할 수 있다. | 실제 PM runner 연결 전 |
| ID-004 | Phase 2 서기 실행 | mock scribe fallback | 실제 Codex 서기 전에도 PM 액션 검증, 그래프 저장, projection을 검증할 수 있다. | 실제 서기 runner 연결 전 |
| ID-005 | 초기 산출물 버전 | 산출물 요청 시 `v001` 요청 문서를 자동 생성 | 직원 실행 전에도 산출물 저장소와 뷰어 흐름을 검증할 수 있다. | Phase 3 이후 |
| ID-006 | Phase 4 직원 실행 | mock worker가 `v002` 산출물 버전을 생성 | 큐 상태 전이와 산출물 버전 연결을 실제 Codex 실행 전 검증할 수 있다. | 실제 worker runner 연결 전 |
| ID-007 | Phase 5 PM 리뷰 | mock PM 리뷰가 산출물 본문의 표식과 위험 문구를 기준으로 승인/재작업/대표 결정을 판정 | 리뷰 파일 저장, 재작업 큐, 반복 제한, 대표 결정 중단 흐름을 검증할 수 있다. | 실제 PM runner 연결 전 |
| ID-008 | Phase 6 결정 반영 | 대표 답변 저장 시 blocked 큐를 재개하고, 답변된 결정은 PM 리뷰에서 대표 판단 근거로 반영 | 결정함 공개 흐름에서 답변 후 작업이 이어지는 전체 흐름을 검증할 수 있다. | 실제 자동 실행 운영 전 |
| ID-009 | Phase 7 수정 요청 | 대표의 수정 요청은 `artifact_revision_requests`에 저장하고 `artifact_revision` 큐로 실행 | 기존 산출물을 보존하면서 새 버전 생성, PM 리뷰, 중복 제외를 한 흐름으로 검증할 수 있다. | 실제 PM 수정 플로우 운영 전 |
| ID-010 | Phase 8 인계 보고서 | 별도 DB 테이블 없이 현재 SQLite/산출물 파일 상태를 읽어 보고서 3개를 재생성 | 인계 문서는 공식 원본이 아니라 사람이 읽는 mirror이므로 현재 데이터 모델을 흔들지 않고 검증할 수 있다. | 실제 인계 보고서 운영 전 |
| ID-011 | Phase 9 데모 데이터 | `scripts/seed-demo.ts`가 `data-sample/`에 개인정보 없는 데모 캠페인을 생성 | 커밋할 샘플 DB 없이도 새 사용자가 핵심 흐름을 체험할 수 있다. | 실제 배포 방식 결정 전 |
| ID-012 | 공개 준비 점검 | `scripts/check-public-ready.ts`로 env, gitignore, 문서, 라이선스, obvious secret pattern을 점검 | GitHub 공개 전 반복 가능한 최소 안전 점검을 둘 수 있다. | 실제 보안 리뷰 전 |
| ID-013 | Codex CLI runner 연결 | `CODEX_RUNNER=codex-cli`에서 PM 답변, PM 액션 서기, 직원 실행, 산출물 수정, PM 리뷰가 `codex exec`를 호출 | 공개 버전이 mock-only가 되지 않도록 실제 실행 경로를 구현했다. 기본값은 안전한 데모를 위해 `mock`으로 둔다. | 모델/비용 정책 확정 후 |
| ID-014 | PM 팀 생성 방식 | PM이 `propose_campaign_team` JSON 액션으로 팀을 제안하고 대표 승인 후 생성 | 역할을 키워드 규칙으로 자동 생성하지 않고, PM 판단을 JSON 스키마로 제한하는 방식이 현재 요구에 맞다. | 조직 운영 정책 확정 후 |
